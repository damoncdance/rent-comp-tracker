If Cloudflare appears there, `_extract_units_from_detail()` sees zero anchors and the parser can still fail because `raw_units=[]` and `ga4_fps=[]` ([src/parsers/rentcafe_optimized.py](/Users/damondance/Documents/Code-Projects/rent-comp-tracker/src/parsers/rentcafe_optimized.py:81)). 3. Prefer Design B: cards primary, detail best-effort. For an unattended daily job, a one-page card snapshot is the more stable availability signal. The main cards expose name, bed/bath/sqft, available count, price, detail URL, and stable RentCafe floorplan ids in one resolved page ([iwt_main.sample.html](/Users/damondance/Documents/Code-Projects/rent-comp-tracker/docs/agent_collab/iwt_bug/iwt_main.sample.html:891), [iwt_main.sample.html](/Users/damondance/Documents/Code-Projects/rent-comp-tracker/docs/agent_collab/iwt_bug/iwt_main.sample.html:914), [iwt_main.sample.html](/Users/damondance/Documents/Code-Projects/rent-comp-tracker/docs/agent_collab/iwt_bug/iwt_main.sample.html:957)). Detail units are higher fidelity but fragile under Cloudflare.

4. Important refinement: do not “prefer detail units if any.” Prefer detail only if it is complete enough, ideally if detail unit count equals the card `availCount` sum and the visited detail pages cover the card URLs. Partial detail success would create false removals/additions and bad leasing velocity. Otherwise use cards for the whole property for that run.

Latent issues I’d flag:

- `_wait_past_cloudflare()` returns the title even after timeout without asserting that target DOM exists ([src/scraper.py](/Users/damondance/Documents/Code-Projects/rent-comp-tracker/src/scraper.py:83)). After main and detail navigation, also wait for `.fp-container`, `a[href*="/floorplans/"]`, or `a[onclick*="applyGAClick"]` as appropriate.

- `_extract_detail_urls()` grabs every `/floorplans/` link and dedupes exact href only ([src/scraper.py](/Users/damondance/Documents/Code-Projects/rent-comp-tracker/src/scraper.py:327)). Normalize query/hash/trailing slash and preferably restrict to `a.floorplan-action-button` / `a.track-apply`, or card-scoped links, to avoid modal/SEO/filter noise if RentCafe adds extra links.

- `_extract_units_from_detail()` is brittle: it only matches single-quoted `applyGAClick(...)` with no escaped quote handling ([src/scraper.py](/Users/damondance/Documents/Code-Projects/rent-comp-tracker/src/scraper.py:353)). Good enough for today’s shape, but fragile.

- `_parse_baths()` only handles integer baths ([src/parsers/rentcafe_optimized.py](/Users/damondance/Documents/Code-Projects/rent-comp-tracker/src/parsers/rentcafe_optimized.py:45)). Schema allows `REAL`, so use decimal parsing eventually.

- Current parser derives `FloorplanId` from 32 bits of md5(name) ([src/parsers/rentcafe_optimized.py](/Users/damondance/Documents/Code-Projects/rent-comp-tracker/src/parsers/rentcafe_optimized.py:116)). Collision risk is low but unnecessary because cards expose `data-floorplan-id` ([iwt_main.sample.html](/Users/damondance/Documents/Code-Projects/rent-comp-tracker/docs/agent_collab/iwt_bug/iwt_main.sample.html:914)). Use the RentCafe id for card-derived records.

- GA4 fallback forces `AvailableCount: 1` ([src/parsers/rentcafe_optimized.py](/Users/damondance/Documents/Code-Projects/rent-comp-tracker/src/parsers/rentcafe_optimized.py:207)). Card fallback should preserve the real `fp-availability` count, not one synthetic unit per floorplan.

- Card-derived units should set `IsEstimated=True`; storage supports it ([src/storage.py](/Users/damondance/Documents/Code-Projects/rent-comp-tracker/src/storage.py:71)) and pricing down-weights estimated comp units ([src/pricing.py](/Users/damondance/Documents/Code-Projects/rent-comp-tracker/src/pricing.py:426)).

Storage/diff risk: append-only snapshots are fine mechanically, but switching from real unit codes to synthetic tier codes changes the semantic shape. `diff_snapshots()` keys entirely by `unit_code` ([src/changes.py](/Users/damondance/Documents/Code-Projects/rent-comp-tracker/src/changes.py:24)), so a representation switch will look like mass removals/additions. It also pollutes leasing velocity and DOM metrics that treat removals as leases ([src/storage.py](/Users/damondance/Documents/Code-Projects/rent-comp-tracker/src/storage.py:462), [src/storage.py](/Users/damondance/Documents/Code-Projects/rent-comp-tracker/src/storage.py:429)). Best mitigation is stable mode selection per run: only emit real units when complete; otherwise emit deterministic card-tier synthetic units marked estimated.
